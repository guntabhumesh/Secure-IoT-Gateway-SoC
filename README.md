[Author](#-author) --- ## 🧭 Overview The **Secure IoT Gateway SoC** is built around one idea: *a small gateway that reads a sensor, encrypts the data in hardware, and sends it out.* | Role in the gateway | Block | Interface | |---|---|---| | Sensor / peripheral bus | **I2C master** | Wishbone B4 behind an AXI→Wishbone bridge | | Data protection | **AES‑128 encrypt / decrypt engine** | AXI4 register-mapped slave | | Uplink / console | **UART** | AXI4 wrapper around an AXI‑Lite UART core | | Control | **VeeR EL2 RISC‑V CPU** *(optional)* | Drives master port `s00` | | Fabric | **2 × 11 AXI4 interconnect** | Decode, arbitration, response routing | Two integration tops share the same interconnect and peripherals, so you can choose how the SoC is driven: | Top | Driven by | Use it for | |---|---|---| | [`soc_top.v`](proj_dir/rtl/interconnect/soc_top.v) | External AXI4 masters (`s00`, `s01`) — BFM-driven | Fast, deterministic peripheral and fabric verification | | [`soc_top_with_veer.v`](proj_dir/rtl/top/soc_top_with_veer.v) | VeeR EL2 core on `s00` (`s01` spare) | Firmware-driven, CPU-in-the-loop simulation | --- ## ✨ Highlights - **AXI4 interconnect, 2 masters × 11 slaves** — every slave owns a 16 MB (`2^24`) window ([`axi_interconnect_wrap_2x11.v`](proj_dir/rtl/interconnect/axi_interconnect_wrap_2x11.v)). - **Three real peripherals + eight reserved slots** — I2C (`m00`), AES‑128 (`m01`), UART (`m02`), dummy slaves (`m03`–`m10`). - **AES encrypt *and* decrypt** — the inverse cipher auto-chains after the forward cipher, so one `LD` pulse gives a full round-trip check. - **VeeR EL2 integration** with a 64→32-bit LSU width adapter, ICCM boot, and JTAG/trace pins exposed. - **12-test full-SoC testbench** covering I2C registers, two NIST FIPS‑197 AES vectors, UART init/TX/RX loopback, dummy-slave routing, and AES soft reset. - **Generator script** for rebuilding the interconnect wrapper for any `M × N` size. - **Verdi waveform evidence** committed under [`proj_dir/tb/`](proj_dir/tb). --- ## 🏗 Architecture ### System block diagram ```mermaid flowchart LR subgraph MASTERS["AXI4 masters"] S00["s00

Firmware must therefore use **32-bit (`awsize = 2`) MMIO accesses only**. With ICCM enabled (the default core configuration) the instruction fetch never reaches the external bus, so the IFU port is tied to a stub. ### Intended data path ```mermaid sequenceDiagram autonumber participant CPU as VeeR EL2 / BFM participant I2C as I2C master (m00) participant AES as AES-128 (m01) participant UART as UART (m02) CPU->>I2C: Configure prescaler, START / READ I2C-->>CPU: Sensor byte(s) in RXR CPU->>AES: Write KEY0..3, TEXT0..3, CTRL.LD AES-->>CPU: CTRL_STATUS.DONE, OUT0..3 = ciphertext CPU->>UART: Write THR (encrypted bytes) UART-->>CPU: LSR.THRE (ready for next byte) ``` ### Figures from the repo | Verdi waveform (I2C + UART + AES) | AXI‑Lite UART IP | |:---:|:---:| | Verdi waveform: I2C, UART and AES activity | AXI-Lite UART block diagram | VeeR EL2 core complex diagram: [`core_complex.png`](proj_dir/doc/RISCV-veer-El2%20core/source/img/core_complex.png) --- ## 🗺 SoC Address Map Identical on `soc_top` and `soc_top_with_veer`. --- ## 📖 Register Maps ### AES‑128 — base `0x0100_0000` Source: module header of [`axi_aes_slave.v`](proj_dir/rtl/aes_core-master/rtl/axi_aes_slave.v) and [`doc/aes core/regmapping`](proj_dir/doc/aes%20core/regmapping). | Offset | Register | Access | Contents | |---|---|---|---| | `0x00` | `CTRL_STATUS` | R/W | `[17]` KDONE · `[16]` DONE · `[2]` RST · `[1]` KLD · `[0]` LD | | `0x04`–`0x10` | `KEY0`…`KEY3` | R/W | Key `[127:96]` … `[31:0]` (MSB word first) | | `0x14`–`0x20` | `TEXT0`…`TEXT3` | R/W | Plaintext `[127:96]` … `[31:0]` | | `0x24`–`0x30` | `OUT0`…`OUT3` | RO | Ciphertext — or, after the inverse-cipher auto-chain, recovered plaintext | ```mermaid stateDiagram-v2 [*] --> Idle Idle --> KeyLoad: CTRL.KLD KeyLoad --> Idle: KDONE Idle --> Encrypt: CTRL.LD (inverse cipher key schedule pre-loaded) Encrypt --> Decrypt: DONE (~11 cycles) — inverse LD fires automatically Decrypt --> Idle: round-trip complete (~11 more cycles) Idle --> Idle: CTRL.RST (soft reset) ``` ### UART — base `0x0200_0000` (decode on `reg[4:2]`) | Offset | `reg[4:2]` | Register | Gate | |---|---|---|---| | `0x00` | 0 | `THR` (write) / `RBR` (read) | `LCR[7]` (DLAB) = 0 | | `0x04` | 1 | `IER` | DLAB = 0 | | `0x08` | 2 | `BAUD_DIVISOR` | DLAB = 1 | | `0x0C` | 3 | `LCR` | always | | `0x14` | 5 | `LSR` (read-only) | always | **Init sequence** (used by `tb_soc_top.v`): 1. `LCR = 0x83` — DLAB = 1, 8N1 2. `BAUD = divisor` — e.g. `868` for 115200 baud at 100 MHz 3. `LCR = 0x03` — DLAB = 0, locks the baud rate 4. `IER = 0x01` — enable RX interrupt (needed for `LSR.DATA_READY`) 5. Write `THR` to transmit ### I2C — base `0x0000_0000` (via `axi_to_wb_bridge`) Standard OpenCores I2C-master WISHBONE map, reached through the bridge (3-bit address, 8-bit data): `PRER_LO`, `PRER_HI`, `CTR`, `TXR`/`RXR`, `CR`/`SR`. Details in [`i2c_specs.pdf`](proj_dir/doc/i2c%20master/i2c_specs.pdf). --- ## 🚀 Quick Start ### Prerequisites - Synopsys **VCS** and **Verdi** - For the VeeR flow: the [chipsalliance/Cores-VeeR-EL2](https://github.com/chipsalliance/Cores-VeeR-EL2) source tree placed in `proj_dir/rtl/Cores-VeeR-EL2/` - For the wrapper generator: Python 3 + `jinja2` - `run_soc_veer.sh` hardcodes `VCS_HOME`, `VERDI_HOME` and a license server — **edit these for your environment** ```bash git clone https://github.com/guntabhumesh/Secure-IoT-Gateway-SoC.git cd Secure-IoT-Gateway-SoC/proj_dir/run ``` ### 1 · Full SoC, BFM-driven (`soc_top` + `tb_soc_top`) ```bash vcs -sverilog -full64 -f run_soc.f -o simv_soc 2>&1 | tee compile_soc.log ./simv_soc | tee sim_soc.log ``` With Verdi FSDB: ```bash vcs -sverilog -full64 -f run_soc.f -o simv_soc \ -P ${VERDI_HOME}/share/PLI/VCS/LINUX64/novas.tab \ ${VERDI_HOME}/share/PLI/VCS/LINUX64/pli.a \ 2>&1 | tee compile_soc.log && ./simv_soc | tee sim_soc.log verdi -f run_soc.f -ssf dump_soc_uart.fsdb & ``` > ⚠️ `run_soc.f` expects UART sources under `../rtl/uartfiles/...`, which is a broken symlink on a fresh clone. See [workarounds](#-known-limitations--how-to-work-around-them). ### 2 · Interconnect + I2C + AES (`run_integrated.f`) ```bash vcs -sverilog -full64 -f run_integrated.f -o simv_integrated \ +define+FSDB \ -P ${VERDI_HOME}/share/PLI/VCS/LINUX64/novas.tab \ ${VERDI_HOME}/share/PLI/VCS/LINUX64/pli.a \ 2>&1 | tee compile_integrated.log ./simv_integrated | tee sim_integrated.log ``` ### 3 · SoC + VeeR EL2 (firmware-driven) ```bash chmod +x run_soc_veer.sh ./run_soc_veer.sh compile # compile only ./run_soc_veer.sh sim # simulate (needs a prior compile) ./run_soc_veer.sh wave # open Verdi on the existing FSDB ./run_soc_veer.sh clean # remove generated artifacts ./run_soc_veer.sh # compile → simulate → open Verdi ``` --- ## 💻 Firmware Notes (VeeR EL2) | Item | Value | |---|---| | Reset vector | `0x8000_0000` | | ICCM base | `0xEE00_0000` | | Firmware load | `$readmemh` `.hex` loaded into `el2_veer_wrapper → el2_mem → iccm` | | How to pass the image | `+hex_file+/path/to/firmware.hex`, or edit the `HEX_PATH` localparam in [`tb_soc_veer_top.v`](proj_dir/tb/tb_soc_veer_top.v) | | MMIO rule | **32-bit word accesses only** (`awsize = 2`) | | Generated headers | [`run/snapshots/default/`](proj_dir/run/snapshots/default) (`common_defines.vh`, `el2_param.vh`, `el2_pdef.vh`, `link.ld`, …) |
